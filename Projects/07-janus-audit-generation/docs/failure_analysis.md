# 失败分析与上线门槛

## 失败桶

| 失败类型 | 诊断信号 | 修复方向 |
| --- | --- | --- |
| 幻觉证据 | 风险标签正确但 bbox/文本片段不存在 | 强制证据合同；人工复核证据 precision |
| 素材内提示注入 | 模型服从图片文字中的“忽略规则” | 系统提示隔离；注入切片；硬策略复算 |
| 政策漂移 | 老政策输出被用于新政策流量 | 每条样本和预测携带 policy_version |
| 过拒/漏拒 | coverage 降低或高风险召回下降 | 分类别阈值；abstain；复核队列 |
| brief 二次引入风险 | 审核通过但生成指令恢复被删元素 | brief 词项扫描；图像生成后再次审核 |
| 奖励投机 | JSON 合法但证据空泛、理由套话 | 奖励分项审计；隐藏评测；硬违规负奖 |
| GRPO 零方差组 | 同一 prompt 的候选奖励完全相同 | 记录 zero_variance；改善采样或奖励分辨率 |
| 跨任务遗忘 | 审核提升但通用理解/生成下降 | 双 holdout；适配器隔离；回滚模型版本 |

## 上线门槛

候选版本只有同时满足以下条件才进入灰度：数据快照和模型 revision 可追溯；test 集主指标及关键切片达标；策略违规率未超过阈值；高风险输出进入人工复核；生成结果完成独立复审；跨任务回归未超过阈值；回滚包和旧模型仍可用。

灰度日志至少保存：请求 ID、素材哈希、政策版本、模型 revision、原始结构化输出、硬策略 verdict、奖励分项或置信度、最终人工动作。日志中不保存无必要的个人敏感原文。
