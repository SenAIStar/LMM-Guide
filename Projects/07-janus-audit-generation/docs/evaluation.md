# 评测协议

## 1. 固定数据边界

- 按 `group_id` 切分，广告活动、原图及近重复版本必须留在同一 split。
- 训练前记录素材 SHA-256、授权编号、政策版本和数据快照编号。
- 阈值只在 validation 集选择，test 集只做一次最终报告。
- 人工复核分歧单独统计，不把争议样本静默改成模型错误或正确。

## 2. 三组基线

1. Janus-Pro 冻结零样本：不训练，只验证原生理解能力和 JSON 服从度。
2. 结构化 SFT：只比较严格合同、证据定位和拒答行为带来的变化。
3. SFT + 文本决策 GRPO：只优化审核 JSON 与安全 brief，不宣称优化图像 token。

## 3. 指标

审核主指标是决策 Macro-F1，同时报告每类召回率，尤其保留高风险类召回。证据指标拆成 precision/recall；结构化输出报告 JSON valid rate；可选择拒答的模型报告 coverage 与 selective error。策略违规率由确定性策略引擎复算，不能由模型自报。

生成侧只评估通过硬策略的 brief：政策通过率、提示词遵循度、盲测偏好和生成后复审通过率。理解与生成 holdout 都与冻结基线比较，回归超过目标阈值即阻断上线。

所有指标按 OCR 密集、小字、多图、政策歧义、提示注入、分布外素材切片。项目中的 `0.84 / 0.03 / 0.01` 是待实测验收目标，不是实验结果。

## 4. 必做消融

- 去掉证据监督，观察 Macro-F1 与证据 precision 的联动。
- 去掉硬策略奖励，统计 reward hacking 和策略违规率。
- `rollout_n=2/4/8`，记录零方差组比例、显存和吞吐。
- token-level 与 sample-level loss aggregation 对比，避免长答案权重偏移。
- 只做 SFT 与 SFT + GRPO 对比，确认收益来自偏好优化而不是数据量变化。
- 冻结/解冻不同模块时同时看理解、生成回归，不能只看审核集。
