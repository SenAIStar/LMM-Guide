# 评测协议

## 1. 固定输入

每个方案使用同一组提示词、条件图、随机种子、采样器、步数和分辨率。一次实验的最小单元是 `(prompt_id, condition_id, seed, variant)`，禁止只保留最好看的结果。

## 2. 分层指标

1. 结构遵循：对生成图重新提取 Canny，使用带像素容差的 Precision、Recall、F1。姿态改用 PCK，分割改用 mIoU，深度改用 AbsRel/RMSE，不能用一个“结构相似度”覆盖所有控制类型。
2. 文本一致：CLIP 类相似度只能衡量语义相关，不能代替结构、品牌身份或美学评测。
3. 分布质量：FID/KID/CMMD 需要固定真实集、相同样本量和相同预处理；小样本下同时报告置信区间，不把 FID 当单一上线指标。
4. 风格或主体一致：使用冻结视觉编码器相似度，并对背景、角度和光照分桶，防止指标只记住近重复图。
5. 人工盲测：隐藏方案名，随机顺序；分别打分结构忠实度、风格一致性、可用性和明显缺陷。
6. 工程指标：记录冷启动、P50/P95 延迟、峰值显存、失败率和单图成本。
7. 安全指标：违规提示的错误放行率与正常提示的误拒率分开报告。

## 3. 必做消融

对比 Base、ControlNet only、LoRA only、ControlNet + LoRA。联合方案扫描 ControlNet scale × LoRA scale；再分别扫描 LoRA rank、训练步数、Canny 阈值、分辨率和采样步数。每个格子使用同一批种子。

## 4. 结果纪律

仓库中的 0.72、65% 和 5% 是待确认的参考门槛，不是实测。只有评测报告包含原始预测、样本级得分、聚合脚本版本、硬件、模型 revision、LoRA 哈希、配置哈希和人工盲测协议后，才能把门槛改写为实际结果。
